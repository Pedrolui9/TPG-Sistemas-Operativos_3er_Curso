Procesos y Administración de Procesos

1. ¿Qué es un Proceso?

Un proceso es un programa en ejecución. Es decir, no es el archivo del programa guardado en el disco, sino la actividad dinámica que se produce cuando ese programa se carga en memoria y el procesador comienza a ejecutar sus instrucciones.

Programa ≠ Proceso
Un programa es un conjunto pasivo de instrucciones almacenado en disco. Un proceso es ese programa "en acción", con sus datos, su estado y los recursos que el sistema operativo le asigna. Un mismo programa puede dar origen a varios procesos ejecutándose al mismo tiempo (por ejemplo, varias ventanas del navegador).

Elementos que componen un proceso

Todo proceso está formado esencialmente por:

📄

Código

Las instrucciones del programa que el procesador ejecuta (también llamado sección de texto).

🔢

Datos

Las variables globales y los datos que el programa utiliza y modifica durante su ejecución.

🧱

Pila (Stack)

Almacena datos temporales: parámetros de funciones, direcciones de retorno y variables locales.

🏷️

Bloque de control (PCB)

Estructura donde el sistema operativo guarda toda la información necesaria para gestionar el proceso.

2. Estado de los Procesos

Durante su vida, un proceso no está siempre ejecutándose. Va pasando por diferentes estados según lo que necesite hacer y según las decisiones del sistema operativo. El estado indica qué está haciendo el proceso en un momento dado.

Modelo de dos estados

El modelo más simple considera solo dos estados: un proceso está en ejecución (usando el procesador) o no en ejecución (esperando su turno). Este modelo es fácil de entender, pero insuficiente, porque no distingue a los procesos que están listos de los que están esperando algún evento.

Modelo de cinco estados

Para representar mejor la realidad, se utiliza el modelo de cinco estados, el más usado para explicar el ciclo de vida de un proceso:

🆕

Nuevo

El proceso acaba de crearse, pero el sistema operativo todavía no lo admitió al grupo de procesos ejecutables.

⏳

Listo

El proceso está preparado para ejecutarse y solo espera que el procesador quede libre para él.

▶️

Ejecución

Sus instrucciones se están ejecutando en el procesador. En un procesador de un solo núcleo, solo un proceso puede estar aquí a la vez.

⛔

Bloqueado

El proceso no puede continuar hasta que ocurra un evento, por ejemplo, la finalización de una operación de entrada/salida.

✅

Terminado

El proceso finalizó su ejecución (normalmente o por error) y el sistema operativo libera los recursos que tenía asignados.

🔀

Transiciones

Los cambios de estado (Listo → Ejecución, Ejecución → Bloqueado, etc.) los decide el sistema operativo mediante el planificador.

Estados suspendidos (modelo ampliado)

Cuando la memoria principal es insuficiente, el sistema operativo puede llevar procesos a disco mediante el intercambio (swapping). Así aparecen dos estados adicionales: Listo/Suspendido y Bloqueado/Suspendido, que corresponden a procesos que fueron trasladados temporalmente fuera de la memoria principal.

Transiciones principales: Nuevo → Listo (admitir) · Listo → Ejecución (despacho) · Ejecución → Listo (fin de tiempo / interrupción) · Ejecución → Bloqueado (solicitud de E/S) · Bloqueado → Listo (evento ocurrido) · Ejecución → Terminado (fin del proceso).

3. Descripción de los Procesos

Para poder administrar muchos procesos a la vez, el sistema operativo necesita mantener información detallada de cada uno. Esa información se organiza en tablas de control y, sobre todo, en una estructura por proceso llamada Bloque de Control de Proceso (PCB).

El Bloque de Control de Proceso (PCB)

El PCB (Process Control Block) es la estructura de datos más importante de un sistema operativo. Contiene toda la información que el sistema necesita para controlar un proceso y para poder detenerlo y reanudarlo más tarde sin perder su estado.

Información típica que guarda un PCB

Elemento Descripción
Identificador (PID) Número único que identifica al proceso dentro del sistema.
Estado Estado actual del proceso (nuevo, listo, ejecución, bloqueado, terminado).
Contador de programa Dirección de la próxima instrucción que debe ejecutarse.
Registros de la CPU Contenido de los registros al momento de interrumpir el proceso.
Información de planificación Prioridad del proceso y datos usados por el planificador.
Información de memoria Punteros a las zonas de memoria asignadas al proceso.
Información de E/S y archivos Dispositivos asignados y lista de archivos abiertos.

Tablas de control del sistema operativo

Además del PCB de cada proceso, el sistema operativo mantiene otras tablas de control: de memoria (qué memoria usa cada proceso), de E/S (estado de los dispositivos), de archivos (archivos en uso) y de procesos (que enlaza todos los PCB). Estas tablas están relacionadas entre sí y permiten al sistema tener una visión completa de todo lo que ocurre.

Concepto clave: Gracias al PCB, el sistema operativo puede "congelar" un proceso, guardar su situación exacta y luego reanudarlo como si nunca se hubiera detenido.

4. Control de los Procesos

El control de procesos abarca todas las acciones que el sistema operativo realiza para crear, ejecutar, suspender, reanudar y finalizar los procesos, así como para cambiar de un proceso a otro.

Modos de ejecución

El procesador puede trabajar en dos modos, para proteger al sistema operativo de los programas de usuario:

👤

Modo usuario

Modo menos privilegiado, en el que se ejecutan las aplicaciones. No pueden acceder directamente al hardware ni a zonas protegidas.

🛡️

Modo núcleo (kernel)

Modo privilegiado en el que se ejecuta el sistema operativo. Tiene acceso total al hardware y a las instrucciones protegidas.

Creación de procesos

Un proceso se crea, principalmente, en situaciones como:

Inicio del sistema · Ejecución de un nuevo programa por el usuario · Solicitud de un proceso ya existente para crear otro (proceso padre que crea un proceso hijo) · Ejecución de un trabajo por lotes.

Cambio de proceso y cambio de contexto

Cuando el sistema operativo decide dar el procesador a otro proceso, realiza un cambio de contexto (context switch): guarda el estado del proceso que estaba ejecutándose en su PCB y carga el estado del proceso que va a ejecutarse a continuación.

Importante: El cambio de contexto consume tiempo del procesador sin realizar trabajo útil para el usuario. Por eso el sistema operativo busca un equilibrio: cambiar de proceso lo suficiente para que todos avancen, pero no tan seguido como para perder demasiado tiempo en la gestión.

5. Gestión de Procesos en UNIX SVR4

UNIX System V Release 4 (SVR4) es una versión clásica de UNIX muy utilizada como referencia para estudiar la administración de procesos, porque su diseño influyó en sistemas actuales como Linux.

Creación de procesos: fork y exec

En UNIX, un proceso crea a otro mediante la llamada al sistema fork(), que genera un proceso hijo casi idéntico al padre. Luego, el hijo suele usar exec() para reemplazar su contenido por otro programa distinto.

# El proceso padre crea un hijo pid = fork(); # se duplica el proceso if (pid == 0) { # Aquí se ejecuta el proceso HIJO exec("programa"); # carga un nuevo programa } else { # Aquí continúa el proceso PADRE wait(); # espera a que el hijo termine }

Estados de un proceso en UNIX SVR4

UNIX SVR4 utiliza un modelo de estados más detallado que el de cinco estados. Entre los más importantes se encuentran:

Estado Significado
Ejecución en modo usuario El proceso se ejecuta con privilegios de usuario.
Ejecución en modo núcleo El proceso se ejecuta dentro del núcleo (por ejemplo, atendiendo una llamada al sistema).
Listo para ejecutar (en memoria) El proceso está preparado para ejecutarse en cuanto el planificador lo elija.
Dormido (bloqueado) en memoria Espera que ocurra un evento; permanece en memoria principal.
Listo / Dormido y suspendido El proceso fue llevado a disco (swap) por falta de memoria.
Creado El proceso acaba de ser creado por fork() y aún no está listo.
Zombie El proceso terminó, pero conserva una entrada para que el padre lea su estado de salida.
Proceso Zombie: Cuando un proceso hijo finaliza y el padre todavía no leyó su resultado con wait(), el hijo queda en estado zombie: ya no se ejecuta, pero aún ocupa una entrada en la tabla de procesos hasta que el padre recoge su información.
