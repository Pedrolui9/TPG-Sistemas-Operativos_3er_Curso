Sistemas Operativos Distribuidos

Un Sistema Operativo Distribuido (SOD) es una colección de computadoras independientes conectadas a través de una red de comunicación, que aparecen ante los usuarios como un único sistema coherente y centralizado.

1. Objetivos de los Sistemas Distribuidos

Propósitos fundamentales al unificar múltiples nodos de procesamiento

01

Transparencia

Hacer que muchas computadoras parezcan una sola. El usuario no necesita saber dónde están guardados los datos físicamente.

Ejemplo real: Google Fotos o Dropbox. Guardas un archivo y lo ves al instante sin preocuparte en qué país o disco duro del mundo se almacenó.
02

Compartición de Recursos

Permitir que varios usuarios usen los mismos equipos, programas o archivos a distancia sin interferir entre sí.

Ejemplo real: Una impresora en una oficina que todos usan desde sus distintas computadoras, o el sistema de un banco con múltiples cajeros.
03

Apertura e Interoperabilidad

Usar reglas estándar para que computadoras de distintas marcas o con sistemas diferentes se entiendan sin problemas.

Ejemplo real: Un "traductor universal". Permite que la app de tu celular (Android o iOS) consulte datos en una computadora central antigua.
04

Escalabilidad

La facilidad para agregar más computadoras al sistema si el trabajo aumenta, sin que el servicio se vuelva lento o se caiga.

Ejemplo real: Netflix estrenando una serie masiva conectando automáticamente miles de servidores en la nube.

2. Arquitecturas de Hardware

Formas en que se conectan físicamente los componentes y equipos

Fuertemente Acoplados

Varios procesadores dentro de una misma caja que comparten la misma memoria física y reloj del sistema (Multiprocesadores).

💡 Ejemplo: Supercomputadoras para simulaciones científicas o entrenamiento avanzado de IA.

Débilmente Acoplados

Computadoras independientes (Multicomputadoras) con su propia memoria local, conectadas mediante red de comunicación.

💡 Ejemplo: Un sistema de Puntos de Venta (POS) en una cadena de supermercados.

Topologías de Red

La estructura geométrica de interconexión (Estrella, Anillo, Bus o Malla) que determina latencia y tolerancia a fallos.

💡 Ejemplo: Redes de fibra óptica malladas donde la información busca rutas alternas.

3. Capas y Modelos de Software

Cómo se organizan los programas para administrar los nodos de la red

SO de Red (NOS)

Cada computadora mantiene su propio SO independiente. El usuario es consciente de las máquinas individuales y usa comandos de red explícitos.

💡 Ejemplo: Windows Server con Active Directory o conexiones por SSH/FTP.

SO Distribuido (DOS)

Un único sistema operativo gestiona globalmente todos los recursos. Los usuarios no perciben dónde se ejecutan sus procesos.

💡 Ejemplo: Sistemas de investigación como Amoeba o Plan 9 que unifican CPUs y memoria física.

Middleware

Capa intermedia que actúa como puente de comunicación heterogénea y gestión de llamadas a procedimientos remotos (RPC).

💡 Ejemplo: Apache Kafka, RabbitMQ o gRPC (el "mesero" del restaurante).

4. Aspectos Críticos del Diseño

Desafíos indispensables al construir un sistema distribuido robusto

Transparencia

Ocultar la complejidad abarcando localización, acceso, migración y replicación.

Migración en vivo de contenedores Docker de un servidor a otro sin interrupción en la pantalla

Sistemas Modulares

Uso del modelo micronúcleo para delegar servicios a espacio de usuario (bloques LEGO).

Sistemas como QNX o MINIX, donde la falla de un controlador de dispositivos no apaga el equipo completo.

Tolerancia a Fallos

Garantizar que el sistema siga operando aunque se rompa un cable o se apague un nodo.

Réplicas bancarias internacionales que mantienen la operación activa aunque caiga un centro de datos.

Sincronización

Balanceo de carga y aseguramiento de que los equipos tengan exactamente la misma hora mediante relojes lógicos/físicos..

Uso del protocolo NTP y Relojes de Lamport para registrar transacciones al milisegundo exacto.
